## زمینه

شاخهٔ اصلی، دامنهٔ آفلاین و پردیس پیش‌نمایش دارد. زنجیرهٔ وابسته، نسخهٔ دامنه، نگهداری PostgreSQL و تحویل رویداد را روی رکوردهای موجود اضافه می‌کند. شکاف اصلی اتصال، طولانی‌شدن مسیر از تصمیم استاد تا تمرین مجاز است. اتصال به Core و شواهد ساخت ۲۳ همچنان پیش‌شرط‌اند.

## گزینه‌ها

| مسیر | اثر |
| --- | --- |
| سه اپلیکیشن مستقل با ذخیره‌ساز جدا | استقلال استقرار بیشتر. در مرحلهٔ پایلوت هماهنگی مجوز، پیشرفت نما و بازیابی پیچیده‌تر می‌شود. |
| تک‌برنامهٔ ماژولار، سه رابط نقش‌محور و کارگر مشترک | یک مرجع عضویت و تراکنش، با امکان کنترل مرزها در کد و قرارداد. برای استقلال بعدی باید جریان داده و وابستگی پیش از استخراج سرویس اندازه‌گیری شوند. |
| یک API عمومی و سیاست‌های متمرکز در رابط کاربر | راه‌اندازی کوتاه‌تر. خطر گسترش دامنه، دوباره‌کاری و ارسال دادهٔ خصوصی به مشتری بالاتر است. |

## تصمیم پیشنهادی

رابط نقش‌محور به لایهٔ کاربرد واحد متصل شود. دامنه و سیاست بدون وابستگی شبکه‌ای قابل آزمون باشند. تعریف نسخه‌دار نقش‌های بانک اطلاعاتی، صف خروجی اتمی، مصرف قابل تکرار و بازخوانی مجاز پس از تغییر دسترسی در همان برش اول آزموده شوند. مرز Core نسخه‌دار و بسته بماند تا مالک قرارداد رسمی و محیط آزمایشی را ثبت کند.

## پیامد و بازبینی

رابط خواندنی دانشجو و فرمان‌های استاد با مجوز و شناسه‌های مشترک سنجیده می‌شوند. رابط HTTP باید مسیر ایجاد اولیه را به مدل وضعیت موجود اضافه کند. قبل از تغییر بیشتر، رفتار لغو تخصیص، لغو عضویت و بازیابی پس از اتصال، به تست‌های رگرسیون تبدیل شود. جداسازی قطعه‌ای برای صوت یا تحلیل سنگین زمانی ارزیابی می‌شود که بار، حفظ حریم خصوصی یا بازیابی مستقل نیاز به آن را نشان دهد.
